# Session notes: 2026-11-25

Branch: `WebhelperFIX` on `muzimran11/cs2mac`. Target: 1080p 85+ fps median on an M4 Air.

## What changed

### Webhelper setup (fresh-install flow)
On a fresh prefix Steam has not downloaded its real `steamwebhelper.exe` yet, so the wrapper
swap was failing. `./cs2mac steam` and `scripts/setup.sh webhelper` now defer the swap when
the file is missing and print instructions to run Steam once, log in, then re-run `setup.sh
webhelper`. README Quick start updated to show the two-pass flow.

### Performance knobs (`scripts/env.sh`)
- `D3DM_ENABLE_METALFX=1` auto-enabled when `CS2MAC_WIDTH >= 1920`. On smaller Apple GPUs the
  regime at 1080p flips from CPU-bound to GPU-bound; spatial upscaling pays off there.
  `CS2MAC_METALFX=0` opts out, `CS2MAC_METALFX=1` forces at any resolution.
- `CS2MAC_ASYNC_COMMIT=1` and `CS2MAC_MULTITHREADED=1` expose the other two D3DMetal env knobs.
- `CS2MAC_MIMALLOC=1` inserts mimalloc into the Wine host process via
  `DYLD_INSERT_LIBRARIES`. Installed alongside the other brew deps.
- `CS2MAC_NICE=1` wraps launch in `nice -n -5`. Off by default.

### Shader warmup (`./cs2mac warmup [map]`)
New subcommand. Loads the map with bots disabled, runs `scripts/warmup/warmup.cfg` which
gives every weapon, cycles scopes, triggers post-process and particle paths, then fires
each weapon at four angles so decal shaders compile for every surface material. Takes
~60-120 s per map. Idempotent per (map, backend, shim hash, MoltenVK hash); mark file at
`~/Library/Application Support/cs2mac/warmup/<backend>-<map>-<hash>`.
`CS2MAC_FORCE_WARMUP=1` redoes it.

### Hybrid arm64 Wine (experimental)
`./cs2mac setup wine_arm64` builds a second Wine configure at `vendor/wine-build-arm64/`
with `--enable-archs=aarch64,x86_64,i386`. Result staged at `vendor/wine-arm64/`, does not
touch the existing Gcenx install. `CS2MAC_WINE_ARM64=1` switches env to it.

The PE side (CS2.exe, D3DMetal) stays x86_64 under Rosetta. What becomes native arm64 is
the Wine loader, `ntdll.so`, `winemac.drv.so`, and `wineserver`. The expected win is on
syscall-heavy paths and wineserver round trips. First build takes 20+ minutes and may
need iteration against aarch64 patch hunks. Build failures print which log to open.

## Bugs fixed during the session
- `taskpolicy -c user-interactive` is not valid on macOS (only `utility` and `background`,
  both demote). It broke every launch with "Could not parse as a QoS clamp". Dropped the
  wrapper. There is no supported CLI knob on macOS to raise QoS above the inherited default.
- Empty bash array under `set -u` broke the launcher at first exec. Fixed by defaulting
  the wrapper to `(env)`, which is a no-op invocation.
- Steam's `-silent` flag was hiding Steam under Wine on macOS (no tray exists). Removed it
  so the main window shows on launch.

## Observed result
First live session at 1920x1080 on `d3dmetal` with MetalFX on: north of 120 fps stable on
the M4 Air. For reference, the M2 Max run documented in `docs/RESULTS.md` is 109.8 median
at the same resolution. The stutters on new map areas and crowded fights are the cold
shader cache; the warmup script should flatten them.

A suspected crash near end of round left no `.ips` in `~/Library/Logs/DiagnosticReports/`,
which means it was not a signal crash (either a hang + force-quit or a clean exit after a
Wine-side assert). To capture it next time, run:

    CS2MAC_DIRECT=1 WINEDEBUG=+seh,+dbghelp ./cs2mac play d3dmetal 1920x1080 2>&1 \
        | tee build/logs/last-play.log

If it dies, `tail -200 build/logs/last-play.log` has the Wine stack.
